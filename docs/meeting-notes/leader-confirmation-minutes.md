# 设备与绩效管理系统需求沟通纪要

整理日期：2026-04-28  
试点范围：101厂房  
用途：提交领导确认需求范围与建设优先级

## 一、会议背景

本次沟通围绕设备与绩效管理系统的建设需求展开。由于目前系统建设仍处于需求梳理和原型验证阶段，第一版建议先以 **101厂房** 为模板进行设计和落地。工厂内存在多个厂房，后续系统需要具备扩展到其他厂房的能力。

本次整理的目标，是先明确整体建设方向、核心业务模块、异常识别规则和后续优先级，为后续系统原型设计、数据对接和功能开发提供依据。

## 二、总体建设目标

系统整体目标是建立一个面向厂房、产线、设备、维修、员工绩效、TPM 和计划管理的数据化平台。通过统一界面查看设备状态、人员工作情况、维修效率和关键指标，帮助负责人及时发现问题、定位原因并推动改善。

系统后续需要覆盖以下核心能力：厂房总览、设备台账、设备放行状态管理、设备详情、OEE / T-loss 指标分析、员工绩效分析、维修与 MTTR 分析、公用设备管理、备件与零部件管理、关键零部件管理、预测性维护、TPM 管理、样件/样品生产计划，以及负责人异常提醒。

## 三、已形成的主要共识

| 事项 | 结论 |
| --- | --- |
| 试点范围 | 第一版先以 101厂房 为模板建设，后续扩展到其他厂房 |
| 设备资产分类 | 设备金额小于 9.5 万元的为费用类采购设备，不属于固定资产；大于 9.5 万元的为固定资产 |
| 设备放行定义 | 放行指设备验收通过，并允许上线使用 |
| 风险设备识别 | 未放行但已经在使用的设备需要作为重点风险项识别并提醒 |
| OEE / T-loss | OEE 和 T-loss 是需要连接数据源的指标，不是单纯手动录入 |
| 公用设备定义 | 公用设备指多个产线或多个工位共用的设备 |
| TPM 管理 | TPM 需要独立界面，不与普通维修管理混在一起 |
| sample 定义 | sample 指样件/样品生产计划 |
| MTTR 异常规则 | 当 MTTR 超过 1440 min 时，系统需要判定为异常，并提醒负责人 |

## 四、主要需求内容

### 1. 厂房总览

需要建设厂房总览页面，用于查看 101厂房整体情况。页面需要展示产线数量、设备数量、供应商数量、设备放行情况、未放行但已使用设备数量、固定资产设备数量、费用类采购设备数量、公用设备数量，以及 OEE / T-loss 和 TPM 等核心指标概览。

该页面的作用是让负责人快速了解厂房整体状态，并能从总览进入设备、指标或异常详情。

### 2. 设备台账与设备详情

需要建立设备台账，记录每台设备的基础信息，包括设备编号、设备名称、所属厂房、产线、工位、供应商、联系方式、采购金额、资产类型、放行状态、当前是否使用等。

从设备列表或总览页面点击设备后，需要进入设备详情页。详情页应展示设备基础信息、供应商信息、资产类型、放行状态、公用设备属性、历史维修记录、OEE / T-loss 指标趋势、相关备件和关键零部件、TPM 计划执行情况，以及设备报废、转移、变更记录。

### 3. 设备放行状态管理

系统需要管理设备放行状态，并能区分已放行正在使用、已放行未使用、未放行未使用、未放行但已经使用四类状态。

其中，未放行但已经在使用的设备属于重点风险项，需要在总览或设备列表中突出显示，并支持提醒负责人。

### 4. OEE / T-loss 指标分析

OEE 和 T-loss 需要通过数据源连接获取。系统后续需要支持按厂房、产线、设备查看指标，支持趋势分析，能够查看 OEE Top 5 问题设备或问题点，以及 T-loss 最高的设备、产线或工位。

指标分析结果需要能够关联到具体设备详情，方便负责人继续追溯原因。对于公用设备，也需要支持独立的 OEE / T-loss 分析。

### 5. 员工绩效分析

需要建设员工绩效透明化功能，统计员工工时、生产效率、个人工作量占比、个人工作效率、PM01 / PM03 工作情况、维修完成时间和维修响应时间。

该模块需要帮助负责人识别维修效率高和低的员工，查看 1 分钟完成、10 分钟完成等典型或异常情况，判断是否存在响应慢、维修慢的问题，并为巡线管理、人员激励、人员培训和管理改进提供依据。

### 6. 维修与 MTTR 分析

系统需要对维修数据进行分析，重点关注 MTTR。需要支持查看设备维修记录、维修开始时间、结束时间、维修耗时，并按员工、设备、产线、厂房分析 MTTR。

会议确认，如果员工日期填写错误，可能导致维修时间异常变长。因此当 MTTR 超过 1440 min 时，系统需要判定为异常，记录异常原因和处理状态，并提示或上报负责人。

### 7. 公用设备管理

公用设备指多个产线或多个工位共用的设备。系统需要支持标记公用设备，记录其服务的产线或工位，并分析其损失情况、维修频率、OEE / T-loss 趋势，帮助找出损失较多或影响范围较大的公用设备。

### 8. 备件、零部件与预测性维护

后续需要建立备件与零部件管理能力，记录每个工位和设备对应的备件、数量、料号、品牌、使用情况、成本等信息，并支持员工查找备件、统计备件消耗和分析成本。

对于关键零部件，例如相机、传感器、重要控制模块等，需要记录品牌、更换时间、故障时间，并分析零部件寿命。系统后续应基于历史故障和更换记录计算平均寿命，在接近寿命周期时提前预警，支持预测性维护。

### 9. TPM 与样品计划

TPM 需要建设独立界面，展示 TPM 计划列表、哪些设备计划做、哪些设备正在做、哪些设备还没做、哪些已完成、哪些未完成，并支持查看每月完成情况、月度完成量占全年计划的比例、人均工作时间和人力需求估算。

sample 指样件/样品生产计划。后续系统需要支持样件/样品生产计划表、日期时间安排、相关设备或产线、当前计划状态，并与工作计划表关联。

### 10. 负责人提醒

系统需要具备异常提醒能力。第一版需要重点关注 MTTR 超过 1440 min、未放行但已使用设备、TPM 超期未完成、关键零部件接近寿命周期，以及 OEE / T-loss 异常等情况。

提醒方式第一版可先采用系统内提醒，后续再根据实际需要扩展邮件、企业微信或其他通知方式。

## 五、优先级建议

| 优先级 | 建设内容 | 说明 |
| --- | --- | --- |
| P0 第一版必须做 | 101厂房总览、设备台账、设备详情页、设备放行状态、未放行但使用设备识别、OEE / T-loss 数据源连接预留、员工维修与 MTTR 分析、MTTR 超过 1440 min 异常判断、TPM 独立界面基础版 | 用于形成系统主体框架，并覆盖当前最重要的管理风险 |
| P1 第二阶段 | 备件与零部件管理、公用设备分析、OEE / T-loss Top 5 分析、关键零部件寿命分析、样件/样品生产计划 | 在第一版基础上补充设备维护、损失分析和计划管理能力 |
| P2 后续优化 | 预测性维护、负责人自动通知、成本分析、多厂房扩展、设备品牌标准化分析 | 面向后续智能化、自动化和跨厂房推广 |

## 六、需领导确认事项

请领导重点确认以下事项：

1. 第一版是否按 101厂房 作为模板先行建设；
2. 第一版 P0 范围是否按上述内容执行；
3. 设备金额等于 9.5 万元时，资产类型应归为固定资产还是费用类采购设备；
4. OEE / T-loss 数据源是否具备连接条件，以及后续由谁提供数据接口；
5. 员工绩效、维修记录、PM01 / PM03、MTTR 等数据当前来源于哪个系统或表格；
6. 负责人提醒第一版是否先做系统内提醒，还是需要同步考虑邮件或企业微信；
7. 是否需要在第一版中支持 Excel 导出或报表导出；
8. 是否需要按厂房、产线、负责人或班组设置数据权限。

## 七、下一步计划

若上述方向确认，下一步建议先完成第一版原型设计，重点包括 101厂房总览、设备台账、设备详情、员工维修与 MTTR 分析、异常提醒和 TPM 基础界面。同时需要同步梳理数据来源、字段口径和指标计算规则，为后续开发和数据接入做准备。
