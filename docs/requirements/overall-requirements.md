# 工厂设备与绩效管理系统总体需求清单 V1

日期：2026-04-28

## 1. 背景与目标

目前对真实产线、设备和业务数据还在熟悉阶段，因此先以 **101厂房** 为试点，整理一版总体需求，用于和业务方、负责人继续对齐。工厂包含多个厂房，系统后续需要具备扩展到其他厂房的能力。

系统的总体目标是建设一个面向厂房、产线、设备、维修、员工绩效、TPM 和计划管理的数据化平台。平台需要帮助负责人看到真实数据、发现异常问题、定位原因，并推动后续管理改善。

整体能力包括员工绩效透明化、维修效率分析、MTTR 异常识别、设备基础信息维护、设备放行状态追踪、OEE / T-loss 指标接入、公用设备分析、备件和关键零部件管理、TPM 管理、样件/样品生产计划管理，以及异常提醒和预测性维护。

## 2. 建设范围与优先级

第一阶段先做 **员工绩效管理**。原因是当前业务最先需要看清楚员工工时、工作量、PM01 / PM03 完成情况、维修效率、个人工作量占比，以及 MTTR 异常问题。

后续阶段再逐步扩展设备台账、设备详情、设备放行管理、OEE / T-loss 数据源连接、公用设备分析、备件管理、关键零部件寿命分析、预测性维护、TPM 独立界面、样件/样品生产计划和多厂房扩展。

| 阶段 | 建设重点 | 说明 |
| --- | --- | --- |
| P0 第一阶段 | 员工绩效管理 | 先解决员工工时、工作量、维修效率、MTTR 异常和负责人提醒 |
| P1 第二阶段 | 设备与指标管理 | 建设设备台账、设备详情、放行状态、OEE / T-loss 接入、公用设备和 TPM 基础界面 |
| P2 后续优化 | 预测和成本分析 | 扩展备件、关键零部件寿命、预测性维护、样品计划、多厂房、自动通知和成本分析 |

## 3. 第一阶段：员工绩效管理

第一阶段需要建立一个员工绩效管理界面，用数据透明展示每位员工的工作情况、维修效率和异常情况。主要使用对象包括厂房负责人、维修负责人、班组长、绩效统计人员和相关管理人员。

系统需要围绕维修和工时数据进行统计分析。核心数据包括员工姓名、工号、所属厂房、所属班组或区域、日期、工时、工作单号、工作类型、PM01、PM03、维修开始时间、维修结束时间、维修耗时、MTTR、设备编号、设备名称、所属产线、所属工位和负责人。

第一阶段需要统计的核心指标包括总工时、总工作量、完成工单数、PM01 数量、PM03 数量、平均维修耗时、平均 MTTR、工作效率、个人工作量占总工作量比例、异常维修记录数，以及 MTTR 超过 1440 min 的异常记录数。

## 4. 员工绩效页面需求

员工绩效页面建议分为三个层级：绩效总览、员工列表和个人详情。

| 页面 | 主要内容 |
| --- | --- |
| 绩效总览 | 展示统计周期、工人总人数、总工时、总工单数、平均维修耗时、平均 MTTR、MTTR 异常数量、PM01 / PM03 占比、工作量占比和绩效排名 |
| 工人列表 | 按工人展示姓名、工号、总工时、完成工单数、PM01 / PM03 数量、平均维修耗时、平均 MTTR、工作效率、工作量占比、异常记录数和排名 |
| 个人详情 | 展示单个员工的基础信息、周期工时、完成工单、PM01 / PM03 分布、每日趋势、维修耗时趋势、MTTR 趋势、参与维修设备、异常记录和工单明细 |

页面需要支持按日期范围、厂房、班组、工人、工作类型、PM01 / PM03、设备、产线和工位进行筛选。

## 5. 维修效率分析需求

系统需要帮助负责人判断员工维修效率的差异。重点关注哪些工人维修完成较快、哪些工人维修完成较慢、哪些记录在 1 分钟内完成、哪些记录超过 10 分钟，以及同一设备或同一类问题下不同员工的维修耗时差异。

这些分析主要用于发现优秀经验、识别培训需求、判断是否存在响应慢或处理慢的问题，并为巡线管理、员工激励和管理改进提供依据。

第一阶段至少需要支持以下 Top 分析：维修时间最长 Top 5、MTTR 异常 Top 5、工作量最高 Top 5、工作量最低 Top 5、效率最高 Top 5 和效率最低 Top 5。

## 6. MTTR 异常判断需求

系统需要增加 MTTR 异常判断逻辑。如果员工日期填写错误，可能导致维修时间异常变长。因此当 MTTR 超过 **1440 min** 时，系统需要自动判定为异常。

异常记录需要进入异常列表，并提示或上报负责人。异常明细中需要展示工人姓名、工号、工单号、设备编号、设备名称、维修开始时间、维修结束时间、MTTR、异常原因、处理状态和负责人。默认异常原因可以标记为“疑似日期填写错误”。

第一阶段提醒方式可以先做系统内提示，后续再扩展为邮件、企业微信或其他通知方式。

## 7. 后续模块需求概览

后续模块先按能力方向保留，不在第一阶段展开实现。

| 模块 | 需求概览 |
| --- | --- |
| 厂房总览 | 以 101厂房 为模板，展示产线数、设备数、供应商数、放行状态、资产分类、公用设备、OEE / T-loss 和 TPM 概览 |
| 设备台账 | 记录设备编号、名称、厂房、产线、工位、供应商、联系方式、采购金额、资产类型、放行状态、使用状态和备注 |
| 设备放行 | 放行指验收通过并允许上线使用。系统需要识别“未放行但已经在使用”的设备，并作为风险项提醒负责人 |
| 设备详情 | 展示设备基础信息、供应商、资产类型、放行状态、公用设备属性、维修记录、OEE / T-loss 趋势、备件、关键零部件、TPM 和变更记录 |
| OEE / T-loss | OEE 和 T-loss 都需要连接数据源。系统后续需要支持按厂房、产线、设备查看指标、趋势和 Top 5 问题 |
| 公用设备 | 公用设备指多个产线或多个工位共用的设备。系统需要分析其服务范围、维修频率、损失情况和指标趋势 |
| 备件与零部件 | 管理工位和设备备件、数量、料号、品牌、使用情况、成本，并支持员工查找和成本分析 |
| 关键零部件 | 标记相机、传感器、重要控制模块等关键部件，记录品牌、更换时间、故障时间，并分析寿命 |
| 预测性维护 | 基于故障时间、更换时间、两次故障间隔和平均寿命，提前提醒负责人准备维护或更换 |
| TPM | TPM 需要独立界面，展示计划设备、正在做的设备、未做设备、完成状态、月度完成情况和人力需求 |
| 样品计划 | sample 指样件/样品生产计划，后续需要支持日期时间安排、相关设备或产线、计划状态和工作计划关联 |

## 8. 已确认业务规则

101 指厂房，第一版先以 101厂房 为例开始做。设备金额小于 9.5 万元的属于费用类采购设备，不属于固定资产；设备金额大于 9.5 万元的属于固定资产，等于 9.5 万元的边界规则后续需要确认。

放行指验收通过并允许上线使用。目前存在一些未放行但已经在使用的设备，后续系统需要识别并提醒。OEE / T-loss 是需要连接数据源的指标。公用设备指多个产线或多个工位共用的设备。TPM 需要单独做界面，不和普通维修混在一起。sample 指样件/样品生产计划。

## 9. 待确认问题

后续仍需要确认 PM01 和 PM03 的准确业务定义、员工工时和维修记录的数据来源、工作效率计算公式、是否需要绩效评分、等于 9.5 万元设备的资产归类、OEE / T-loss 数据源位置和接口方式、负责人提醒方式、是否需要导出 Excel 或报告，以及是否需要按负责人或区域做权限控制。
