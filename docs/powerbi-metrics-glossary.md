# Power BI 指标与业务缩写说明 V1

整理日期：2026-05-07  
来源：`docs/reference/powerbi.docx` 中记录的现有 Power BI 界面内容和员工口头介绍笔记

## 1. 文档目的

本文用于整理现有 Power BI 界面中涉及的指标、缩写和业务口径，方便后续建设前端展示界面、员工绩效模块和设备管理模块时统一理解。

当前阶段数据暂时无法实时连接企业数据库，第一版可以先通过从数据库导出的 Excel / CSV 文件进行展示。后续接入数据库时，应尽量复用本文中的指标口径和字段定义。

## 2. 业务区域与设备范围

现有记录中提到，工厂内部可按以下区域或部分划分：

| 区域 / 部分 | 说明 |
| --- | --- |
| MXM | 工厂内部区域或业务单元，具体范围待进一步确认 |
| MXL & MXR | 工厂内部区域或业务单元，具体范围待进一步确认 |
| MXS | 工厂内部区域或业务单元，具体范围待进一步确认 |
| MXC | 工厂内部区域或业务单元，具体范围待进一步确认 |
| MXG | 工厂内部区域或业务单元，具体范围待进一步确认 |

每个区域下包含不同类型的设备，例如包纸机、割纸机、动平衡测试机等。后续系统需要支持按区域、产线、设备类型或具体设备进行筛选。

## 3. 缩写与业务术语

| 缩写 / 术语 | 含义 | 说明 |
| --- | --- | --- |
| OEE | Overall Equipment Effectiveness，设备综合效率 / 设备综合利用率 | 用于衡量设备有效产出能力，目标通常希望大于等于 90% |
| OEE Loss | OEE 损失 | 指导致 OEE 未达目标的损失来源 |
| T-loss | Technical loss，技术损失 | OEE 损失的一类，通常与设备、技术、故障等相关 |
| O-loss | Other loss，其他损失 | OEE 损失的一类，具体业务范围待确认 |
| C-loss | Changeover loss，换型损失 | OEE 损失的一类，通常与换型、切换、调整相关 |
| Q-loss | Quality loss，质量损失 | OEE 损失的一类，通常与质量问题、报废、返工等相关 |
| P-loss | People loss / Personnel loss，人员损失 | OEE 损失的一类，通常与人员、排班、操作等相关，具体口径待确认 |
| MTTR | Mean Time To Repair，平均维修时间 | 从故障或维修开始到维修完成的平均耗时 |
| MTBF | Mean Time Between Failures，平均故障间隔时间 | 两次故障之间的平均运行时间，用于衡量设备可靠性 |
| Reaction Time | 维修响应时间 | 从故障/Andon/维修需求产生到维修人员响应的时间 |
| Repair Time | 维修处理时间 | 从维修开始到维修完成的实际处理时间 |
| Andon | 现场异常呼叫 / 安灯系统 | 用于现场异常报警、等待和响应管理 |
| Andon Waiting Time | Andon 等待时间 | 从现场发出 Andon 到被响应或处理前的等待时间 |
| Downtime | 停机时间 | 设备或产线无法生产的时间 |
| Downtime Rate | 停机率 | 停机时间占计划生产时间或总时间的比例 |
| Output | 产出 | 一段时间内的生产数量 |
| POT | 排班 | 员工或产线的排班信息，具体系统口径待确认 |
| KPI | Key Performance Indicator，关键绩效指标 | 用于衡量业务表现的核心指标 |
| Last Rolling Data | 最近滚动周期数据 | 按最近一段滚动周期统计的 KPI 数据 |
| PM01 | 设备故障紧急维修 | 用于记录设备发生故障后的紧急维修工单 |
| PM03 | 计划维修维护 | 用于记录计划性维修维护，例如产线整改、设备改进等 |
| S | Safety，安全 | 安全相关指标或分类 |
| Q | Quality，质量 | 质量相关指标或分类 |
| FPY | First Pass Yield，一次性通过率 | 产品一次生产即合格的比例 |
| Rework | 返工 / 回炉重造 | 需要返工处理的产品或设备数量 |
| Scrap | 报废 | 无法返工或继续使用，需要报废的数量 |

## 4. Power BI 现有指标页面分类

根据 `docs/reference/powerbi.docx` 记录，现有 Power BI 界面主要包含以下指标页面或明细页面。

### 4.1 OEE 与损失分析

| 页面 / 指标 | 含义 |
| --- | --- |
| OEE & OEE-loss trend | OEE 与 OEE 损失趋势 |
| OEE trend | OEE 趋势 |
| OEE detail | OEE 明细 |
| OEE-loss trend | OEE 损失趋势 |
| OEE T-loss detail | OEE 技术损失明细 |
| OEE O-loss detail | OEE 其他损失明细 |
| OEE C-loss detail | OEE 换型损失明细 |
| OEE Q-loss detail | OEE 质量损失明细 |
| OEE P-loss detail | OEE 人员损失明细 |

OEE 的理解示例：如果一把产品平均 28 秒生产出来，一天生产 1000 把，则理论生产时间为 `1000 * 28s`。用该时间与总工作时间进行比较，可以得到设备或产线的 OEE 表现。现有口径中提到 OEE 目标希望大于等于 90%。

### 4.2 MTTR / MTBF / 响应时间

| 页面 / 指标 | 含义 |
| --- | --- |
| MTTR trend | 平均维修时间趋势 |
| MTTR detail | 平均维修时间明细 |
| MTBF trend | 平均故障间隔时间趋势 |
| MTBF detail | 平均故障间隔时间明细 |
| Reaction time trend | 维修响应时间趋势 |
| Reaction time detail | 维修响应时间明细 |
| Reaction time quarterly trend selected | 维修响应时间季度趋势 |
| Reaction time quarterly detail | 维修响应时间季度明细 |

这类指标主要用于衡量维修团队响应速度、维修处理效率和设备可靠性。其中 MTTR 越低通常表示维修效率越高，MTBF 越高通常表示设备越稳定。

### 4.3 Andon 与停机分析

这类指标主要用于分析设备停机、维修等待和现场响应问题。后续如果做设备详情页或公用设备分析，可以参考这些指标作为下钻入口。

## 5. 员工绩效相关指标

现有 Power BI 中已经包含与员工绩效相关的指标，后续员工绩效系统可以优先参考这些口径。

| 指标 | 含义 | 建议在前端中的展示方式 |
| --- | --- | --- |
| 员工维修工时 | 员工用于维修相关工作的工时 | 按员工、班组、日期统计 |
| 员工出勤小时 | 员工实际出勤时间 | 作为维修效率计算分母 |
| 员工接单数量 | 员工接收或完成的维修工单数量 | 可作为工作量指标 |
| 员工维修效率 | 员工单位出勤时间内完成的维修工作量 | 可用于员工绩效排名 |
| 维修组员工整体维修效率 | 整个维修组的整体效率 | 可用于班组或团队绩效总览 |

当前已确认的维修组员工整体维修效率公式为：

```text
维修组员工整体维修效率 = (PM01 + PM03) / 出勤时间
```

其中：

```text
PM01 = 设备故障紧急维修
PM03 = 计划维修维护，例如产线整改、设备改进
```

后续员工绩效模块可以先采用同样口径：

```text
员工维修效率 = 员工完成的 PM01 和 PM03 工单数量 / 员工出勤小时
```

如果后续业务方提供更正式的绩效公式，再替换计算逻辑。

## 6. 生产与质量相关指标

| 指标 | 含义 |
| --- | --- |
| Output trend | 产出趋势 |
| Output detail | 产出明细 |
| FPY | 一次性通过率 |
| Rework | 返工 / 回炉重造数量 |
| Scrap | 报废数量 |
| S Safety | 安全相关指标 |
| Q Quality | 质量相关指标 |

这类指标与设备和维修也存在关联。例如质量损失、返工、报废可能影响 OEE 中的 Q-loss；漏气维修可能需要关联到具体设备、产线、维修人员和维修类型。

## 7. 对当前前端系统的影响

当前我们正在建设的前端系统第一阶段可优先覆盖员工绩效和维修效率相关内容，包括员工维修工时、员工出勤小时、员工接单数量、PM01 / PM03 数量、员工维修效率、MTTR、Reaction Time 和 Repair Time。

初期由于数据只能从企业数据库下载为 Excel，因此前端不应直接依赖 Excel 文件结构，而应通过后端统一 API 获取数据。建议系统结构保持为：

```text
Excel / CSV 导出文件
        ↓
后端数据清洗与指标计算
        ↓
/api/worker-performance
        ↓
前端绩效总览、工人列表、个人详情、异常分析
```

后期当数据库连接条件具备后，只需要将后端数据来源从 Excel / CSV 替换为数据库查询，前端页面和 API 结构尽量保持不变。

## 8. 待确认问题

| 问题 | 说明 |
| --- | --- |
| MXM、MXL & MXR、MXS、MXC、MXG 的准确组织含义 | 需要确认这些是厂房、区域、部门还是产线分类 |
| O-loss、P-loss 的准确业务定义 | 当前根据常见含义推测为其他损失、人员损失，需业务确认 |
| 维修率、维修单率的计算公式 | 需要确认分子和分母分别是什么 |
| Reaction Time 的开始和结束节点 | 例如从 Andon 触发到接单，还是从工单创建到维修开始 |
| Repair Time 与 MTTR 的关系 | 需要确认两者是否完全一致，还是 Repair Time 只统计实际维修处理时间 |
| 员工出勤小时的数据来源 | 需要确认来自排班、考勤还是 Power BI 已有表 |
| POT 的准确字段来源 | 当前理解为排班，但需要确认具体系统或表 |
| 漏气维修的统计口径 | 需要确认属于维修问题、质量问题，还是设备专题 |
